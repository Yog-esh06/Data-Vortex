# Social Engine — Round 1 (Phase 1): Data Recovery & EDA

Restoring the corrupted intake pipeline of the "Social Engine" system by cleaning a corrupted social-media-like dataset, handling missing values, detecting anomalies, and running exploratory data analysis.

## 📂 Repository Contents

| File | Description |
|---|---|
| `Round1_Phase1_Data_Recovery_Local.ipynb` | Full pipeline: audit → cleaning → anomaly detection → EDA, with charts. Runs locally in VS Code / Jupyter |
| `Social_Engine_Posts_Corrupted.csv` | Original corrupted dataset (12,360 rows) |
| `Social_Engine_Users.csv` | Original users dataset (1,500 rows) |
| `Social_Engine_Posts_Cleaned.csv` | Cleaned & standardized posts dataset (12,000 rows) — generated by the notebook |
| `Social_Engine_Users_Cleaned.csv` | Cleaned & standardized users dataset — generated by the notebook |

## 🧹 Cleaning Summary

- Removed 360 exact duplicate rows
- Standardized 3 mixed timestamp formats (Unix epoch, ISO 8601, `DD-MM-YYYY`) into one datetime column
- Repaired mojibake text (`Ã©`) and unescaped HTML entities (`&amp;`)
- Resolved missing/`"NULL"` `text_content` and `platform` values
- Flagged and corrected 509 impossible **negative likes** values (imputed via platform median)
- Verified referential integrity: 0 orphan posts, 0 duplicate users, 0 negative followers

## 📊 Key Insights

- Platform mix is nearly even (~17% each across Facebook, YouTube, Twitter, Reddit, Instagram)
- Engagement is flat across the 12-month window — no strong seasonality
- `follower_count` shows ~zero correlation with engagement — reach doesn't predict engagement
- `likes` drives ~89% of total engagement variance

## 🚀 How to Run

1. Clone this repo
2. Install dependencies: `pip install pandas numpy matplotlib`
3. Open `Round1_Phase1_Data_Recovery_Local.ipynb` in VS Code or Jupyter (the two corrupted CSVs are already in the same folder, so no path edits are needed)
4. Run all cells — the cleaned CSVs will be regenerated in the same folder
